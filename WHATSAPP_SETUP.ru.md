# Вход WhatsApp — GlassMarket 9.15

## Что проверено и что ещё нужно

Код создан поверх APK 9.14 и актуального server.js, без замены приложения на Flutter. Изучены JSON-схема сервера и публичные ответы работающей базы. Приватный data/db.json действующего процесса недоступен; настоящие номера и аккаунты не изменялись. Тесты работают исключительно на отдельных временных базах.

Для запуска нужны Meta WhatsApp Business Platform, принимающий сообщения номер и 4 значения в секретах. Доступ к значениям секретов Meta в этой сессии не предоставлен. Код не может самостоятельно подключить ваш номер к Meta.

Сервер сейчас запускается в GitHub Actions примерно на 6 часов с новым временным адресом trycloudflare.com при каждом запуске. Это тестовая инфраструктура, не постоянный сервер. Для реальной эксплуатации нужны постоянный HTTPS-адрес, постоянно работающий Node-процесс и постоянный диск для data/db.json. Пока адрес временный, после каждого перезапуска меняйте Callback URL в Meta. Обычная ссылка GitHub Pages не заменяет сервер webhook.

## Бесплатная схема

Пользователь сам отправляет входящее сообщение. Сервер не вызывает WhatsApp Graph API, не отправляет шаблоны, сообщения, подтверждения или read receipts. HTTP 200 на webhook — техническое подтверждение доставки Meta, не сообщение пользователю. В коде нет платного провайдера и не нужен WhatsApp access token для отправки. Нельзя обещать бесплатность номера, хостинга или будущих тарифов Meta.

## 1. Настроить Meta и секреты GitHub

1. Откройте https://developers.facebook.com/apps/ и выберите своё приложение Meta (не Android APK).
2. Добавьте продукт WhatsApp, если его ещё нет. Перейдите в WhatsApp → API Setup / Настройка API. В новом интерфейсе это может называться Use cases → WhatsApp → API Setup.
3. Подключите номер WhatsApp Business Platform, который может ПРИНИМАТЬ сообщения. Запишите номер целиком с кодом страны, без `+`, пробелов и скобок. Это `WA_LOGIN_NUMBER`. Не используйте номер покупателя.
4. На той же странице найдите **Phone number ID / ID номера телефона**. Это отдельный числовой идентификатор, а не сам телефон. Это `WA_PHONE_NUMBER_ID`.
5. Откройте App settings / Настройки приложения → Basic / Основное → App Secret → Show / Показать. Скопируйте в `APP_SECRET`. Это НЕ App ID и НЕ временный access token. Не отправляйте секрет в чат и не добавляйте в файлы проекта.
6. Придумайте отдельный длинный случайный `VERIFY_TOKEN` (не пароль аккаунта), например создайте 32 случайных байта командой `openssl rand -hex 32`. Он нужен для первоначальной проверки адреса Meta.
7. Откройте https://github.com/somontj5/server.js → Settings → Secrets and variables → Actions → New repository secret.
8. Создайте четыре секрета, каждый отдельной записью: `APP_SECRET`, `VERIFY_TOKEN`, `WA_LOGIN_NUMBER`, `WA_PHONE_NUMBER_ID`.
9. Выданный GitHub App доступ не имеет разрешения `workflows`: GitHub отклонил изменение `.github/workflows/server.yml`. Поэтому этот файл оставлен без изменений. Добавьте передачу секретов вручную: Code → `.github/workflows/server.yml` → карандаш Edit → в шаге **Run server (~5h50m)** найдите `env:` и добавьте следующие строки на том же уровне отступов, что `BOT_TOKEN`. Нажмите **Commit changes**. Здесь должны быть именно ссылки на Secrets, не их реальные значения:

```yaml
          VERIFY_TOKEN: ${{ secrets.VERIFY_TOKEN }}
          APP_SECRET: ${{ secrets.APP_SECRET }}
          WA_LOGIN_NUMBER: ${{ secrets.WA_LOGIN_NUMBER }}
          WA_PHONE_NUMBER_ID: ${{ secrets.WA_PHONE_NUMBER_ID }}
          TRUST_CF_PROXY: 'true'
```

   Перезапуск требуется после изменения секретов/workflow. Без этих строк WhatsApp безопасно выключен с ответом 503; Telegram сохранён.
10. Не запускайте второй процесс на той же JSON-базе. Дождитесь завершения текущего GitHub Actions запуска и сохранения базы шагом **Save DB for next run**. Затем Actions → GlassMarket test server (6h) → Run workflow → main → Run workflow. Принудительная отмена работающего запуска может потерять изменения после последней резервной копии. Наличие `if: always()` не гарантирует сохранение при жёсткой отмене.
11. Откройте свежий `server-url.txt` в репозитории. К этому адресу добавьте `/webhooks/whatsapp`. Например: `https://ВАШ-СЕРВЕР/webhooks/whatsapp`.

Рекомендуется перенести сервер на постоянный адрес до подключения настоящих покупателей. Не стирайте и не подменяйте существующий data/db.json. Новые поля добавляются рядом со старыми; Telegram остаётся рабочим.

## 2. Проверить webhook кнопкой Meta, без публикации Android-приложения

1. В Meta откройте WhatsApp → Configuration / Конфигурация → Webhook → Edit. В некоторых версиях панели: Webhooks → объект WhatsApp Business Account.
2. В **Callback URL** вставьте полный HTTPS-адрес с `/webhooks/whatsapp`.
3. В **Verify token** вставьте точно то же значение `VERIFY_TOKEN`, которое сохранили в GitHub Secrets.
4. Нажмите **Verify and save / Проверить и сохранить**. Успех означает, что GET проверил секрет и вернул `hub.challenge`.
5. Найдите поле **messages** → **Subscribe / Подписаться**. Проверьте, что приложение подписано на нужный WhatsApp Business Account; при стороннем/уже существующем WABA может потребоваться отдельная подписка приложения на этот WABA в настройках интеграции Meta.
6. Рядом с **messages** нажмите **Test / Test webhook / Проверить**, затем **Send to my server / Отправить на мой сервер**, если эта кнопка предлагается. Названия могут отличаться по языку панели.
7. Ожидайте успешную доставку: HTTP **200**, тело `EVENT_RECEIVED`. Meta должна подписать запрос настоящим App Secret. Ошибка **403** означает отсутствие/ошибку подписи или неверный секрет; НЕ отключайте проверку подписи ради теста.
8. Стандартный пример Meta содержит вымышленный номер, другой Phone number ID и обычный текст, а не ваш свежий код. Он проверяет доставку и обработку webhook, но **не должен выполнять вход**. Это ожидаемо. Успех Test webhook НЕ доказывает владение настоящим номером.
9. Для такой проверки не требуется публикация APK в Google Play. Режим Development в Meta и доступные тестовые роли/номера регулируются отдельно самой Meta. Если тестовый номер Meta не принимает реальные входящие сообщения, кнопка Test webhook всё равно проверит доставку, а для полного входа нужен зарегистрированный принимающий business-номер.

Если сервер вернул 503 — проверьте четыре секрета и перезапуск нового кода. 404 обычно означает старую версию сервера/неверный путь; временный tunnel может быть уже закрыт.

## 3. Проверить настоящий вход с телефона

1. Сохраните важные локальные черновики. APK подписан НОВЫМ ключом: Android не установит его поверх версии со старой подписью. Удаление старой версии удалит её локальные данные. Серверные данные этим не удаляются.
2. Установите APK 9.15 вручную. Публикация в Google Play не нужна.
3. Откройте профиль → **Войти: WhatsApp / Telegram** → **Войти через WhatsApp**. Можно также нажать действие, требующее входа, например размещение объявления.
4. Приложение получит случайный код вида `ATUSH` и 24 случайных шестнадцатеричных символа. Не заменяйте его коротким 4-значным кодом: длинный код защищает от подбора. Копировать вручную не надо.
5. Откроется WhatsApp с правильным бизнес-номером и готовым текстом. Проверьте получателя и нажмите **Отправить**. Одного открытия WhatsApp недостаточно.
6. Вернитесь в GlassMarket. Приложение проверяет состояние раз в 2,5 секунды; после подписанного сообщения Meta оно войдёт под подтверждённым WhatsApp-номером.
7. Повторно отправьте тот же текст с другого номера: привязка сессии измениться не должна. Не создавайте новый код в процессе первой проверки.
8. Выйдите и повторите вход с тем же WhatsApp-номером: должен открыться тот же WhatsApp-аккаунт.
9. Создайте новый код и не отправляйте его 5 минут. После этого вход не должен пройти, получите новый код.
10. Если вход не произошёл: убедитесь, что Meta доставляет именно **входящее text-сообщение** на подписанный WABA, `metadata.phone_number_id` совпадает с `WA_PHONE_NUMBER_ID`, сервер жив и URL не сменился. В Meta Development проверьте ограничения тестовых пользователей и номер отправителя.

## Важно о старых аккаунтах

Старый `phone` — редактируемый контакт продавца, а не подтверждённая личность. Поэтому WhatsApp использует отдельное серверное поле `waPhone`, которое клиент не может редактировать. Автоматического объединения со старым Telegram-аккаунтом по контактному номеру НЕТ: иначе злоумышленник мог бы указать чужой номер в профиле и получить чужой аккаунт. Чтобы пока пользоваться прежними объявлениями, входите через прежний Telegram. Безопасная привязка двух способов входа из уже авторизованного профиля — отдельная задача.

## Реализация и проверки

- `POST /auth/whatsapp/start`: sessionId, отдельный 256-битный sessionSecret, 96-битный код, wa.me-ссылка; срок 300 секунд.
- `POST /auth/whatsapp/check`: JSON `{ "sessionId": "..." }`, заголовок `X-WA-Session: sessionSecret`. Не передавайте секрет в URL. Без секрета нельзя получить номер/токен, даже зная sessionId или код сообщения.
- `GET /webhooks/whatsapp`: проверка mode и VERIFY_TOKEN, challenge или 403.
- `POST /webhooks/whatsapp`: HMAC-SHA256 строго по raw bytes, timing-safe сравнение, тело до 256 КБ, фильтр Phone number ID, отправителя, возраста и типа сообщения.
- Код хранится в базе хешем; после первого подтверждения его хеш удаляется. Дубли Meta не меняют номер. Секрет сессии хранится только хешем. Повторный опрос после потери ответа возвращает тот же токен только владельцу sessionSecret; logout блокирует повторную выдачу.
- Новая секция `whatsappAuth.sessions` хранит короткоживущие заявки; `whatsappAuth.limits` — ограниченные по времени счётчики с HMAC-ключами, без открытых IP. Существующие db.sessions используются для обычной авторизации API.
- Лимит выдачи кодов: 10 за 15 минут/IP; проверок: 1200 за 15 минут/IP; сообщений с кодами: 10 за 15 минут/номер. За общим NAT несколько покупателей делят лимит IP.
- Заголовок cf-connecting-ip доверенный только при TRUST_CF_PROXY=true и соединении с loopback от локального cloudflared. При другом reverse proxy настройте доверие отдельно, не доверяйте произвольному X-Forwarded-For.
- Коммит базы атомарный через временный файл + rename. Подтверждение записывается до ответа 200, без сетевых вызовов/отправок сообщений.
- `npm test`: существующие регрессионные тесты + `test-whatsapp.js`; включает HTTP-интеграцию настоящего server.js с отдельной временной базой. Настоящий WhatsApp/Meta не имитируется заявлением об успешном реальном входе: его нужно проверить шагами выше.

Новый Android signing key хранится локально в игнорируемой `.local-build/glassmarket-9.15-release.jks`, пароль — `.local-build/release-password`. Это конфиденциальные файлы: НЕ коммитьте их в публичный репозиторий. Сохраните их отдельно в защищённом хранилище для следующих сборок. Публичный SHA-256 сертификата добавлен к существующим fingerprints в pages/assetlinks.json; настройки публикации GitHub Pages не менялись.
